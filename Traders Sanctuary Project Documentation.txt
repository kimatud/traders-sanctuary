1. Project Overview
--------------------------

Traders Sanctuary is a comprehensive web application designed to be a central hub for forex traders. [cite: 1] It combines community features, educational resources, and a powerful, role-based trading journal into a single, cohesive platform. 

The application is built as a single-page React application embedded directly within an HTML file, utilizing Firebase for backend services and a few server-side PHP scripts for specific functionalities. 

The core philosophy is to provide tailored experiences for different user levels: Guests, Members, Premium Members, and Administrators. 

--------------------------
2. Core Features & User Roles
--------------------------

The application is built around a robust role-based access control system managed in Firebase.

-- Guest --
- Can explore the landing page and learn about the community. 

-- Member (Default Role) --
- Access to the main dashboard. 
- View announcements and study materials.
- Use the basic "My Trading Journal" for simple notes.
- Submit testimonials for admin approval.
- Access the public Discord community widget. 

-- Premium Member --
- Inherits all Member permissions.
- Gains access to the Premium Trading Journal.
- Journal features include automated P&L and Risk/Reward (RR) calculation.
- Mandatory screenshot uploads for trade execution are required. 
- Receives a one-time link to the exclusive premium Discord server. 

-- Administrator --
- Inherits all Premium Member permissions automatically.
- Access to the Admin Panel to manage users, announcements, testimonials, study materials, and certificates.

3. Technology Stack
--------------------------

The project uses a modern, serverless-first approach.

- Frontend:
  - React (v18): The entire user interface is built as a single React application, imported via an ES Module CDN.
  - HTML5 & CSS3: The foundation of the application.
  - Tailwind CSS: A utility-first CSS framework used for all styling.
  - Lucide React: Used for a clean and consistent icon set.
  - Three.js: Powers the interactive particle animation on the landing page.

- Backend & Database:
  - Firebase Firestore: The primary NoSQL database for storing all user data, journal entries, and public content.
  - Firebase Authentication: Manages user sign-up, login, and sessions.
  - PHP: Used for server-side file uploads to a local server.

- Third-Party APIs & Services:
  - Alpha Vantage API: Provides real-time market data for automatic calculations in the premium journal.
  - Tawk.to: A live chat widget integrated for user support.

--------------------------
4. File Structure & Setup
--------------------------

The project runs from a few key files on a standard web server with PHP support.

- react_app.html (Main File):
  - This is the entry point for the entire application.
  - It contains the HTML structure, all CSS styles, and the complete React application code.

- PHP Scripts (Backend Handlers):
  - These scripts handle all file uploads: trade screenshots, study materials, and certificates. They validate files and save them to the appropriate server directory.

- Server Directories:
  - Writable directories (`trade_screenshots/`, `study_materials/`, `funded certificates/`) must be created manually on the server for storing file uploads.

6. Core Architecture & Concepts
--------------------------

-- Single-Page Application (SPA) Logic --
The app mimics a multi-page website without ever reloading the page.
- State-Based Routing: A React state variable, `currentPath`, tracks the current URL (e.g., /dashboard).
- History API: The `handleNavigate` function uses `window.history.pushState()` to change the URL in the browser, allowing for back/forward navigation.
- Conditional Rendering: A `switch` statement in the main `App` component renders the correct page component based on the `currentPath` state.

-- State Management (React Context) --
React Context provides global data to all components.
- AuthContext: Provides authentication information (`user` object, `isAuthReady` status) and functions (`login`, `logout`) to the entire application.
- ThemeContext: Manages the active theme (`light`, `dark`, or `system`) and makes it available to all components for consistent styling.

7. Component Breakdown
--------------------------

-- Core & App Structure --
- AuthProvider: Manages all Firebase authentication and user profile data.
- ThemeProvider: Manages the application's theme.
- App: The central component that handles routing, global state, and page visibility.
- Header: The sticky navigation bar.
- Footer: The site's footer.

-- Pages --
- LandingPage: The main public home page (/).
- Dashboard: The primary hub for logged-in members (/dashboard).
- AdminDashboard: A protected area for administrators (/admin).
- PremiumPage: The sales page (/premium) for users to upgrade.
- ContactPage: The "Contact Us" page (/contact).
- AboutPage, PrivacyPolicyPage, TermsPage: Static content pages (/about, /privacy, /terms).

-- Modals --
- AuthModal: For Login, Registration, and Password Reset.
- TermsModal: A mandatory pop-up for new users to accept the Terms of Service.
- MessageModal: A notification "toast" for success or error messages.
- AnalyticsDashboardModal: The main, comprehensive dashboard for analyzing trading performance.
- MonthlyAnalyticsModal: A drill-down modal showing a performance dashboard for a single month.
- PairAnalyticsModal: A drill-down modal showing a performance dashboard for a single instrument/pair.

-- Dashboard & Analytics Components --
- PremiumTradingJournal: The component for premium users to log and view trades.
- JournalFormModal: The detailed form for logging a new trade with auto-calculations.
- DashboardContent: A reusable component that renders the visual layout of all analytics dashboards.
- Helper/Widget Components:
    - LoadingComponent: The animated text used for loading states.
    - SummaryStat, AdvancedStatItem, StatCard: Reusable cards for displaying individual statistics.
    - createBarChart: A helper function that generates a pre-configured bar chart.
    - PaginationControls: The "Previous/Next" buttons for paginating tables.

--------------------------
8. Key Functions & Logic
--------------------------

- useIdleTimer (Custom Hook): In the `App` component, this hook tracks user inactivity and triggers an automatic logout after 15 minutes for security.
- PDF Generation (`handleDownloadPdf`): In the analytics modals, this function uses `html2canvas` to render the dashboard's HTML content to a canvas, then uses `jsPDF` to convert it into a downloadable PDF.

--------------------------
9. Backend & External Services
--------------------------

- Tawk.to: Provides the third-party live chat widget.

10. Maintenance & Future Development
--------------------------

-- How to Add a New Page --
1. Create the Component: Write a new React component for the page.
2. Add the Route: In the `App` component, add a new `case` to the `switch` statement for the new path.
3. Add a Link: Add a link to the new page in the `Header` or `Footer`.

-- Potential Improvements --
- Transition to Firebase Storage: Migrating file uploads to Firebase Storage would improve security and scalability. 
- Advanced Journal Analytics: The application is well-positioned to add more advanced analytics, like win rate by pair or an automated lot size calculator.
- Componentization: For long-term maintenance, the single React script could be broken down into separate files using a build tool like Vite.
